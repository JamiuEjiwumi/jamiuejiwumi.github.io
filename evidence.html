01 / RELEASE ENGINEERING

Build once, promote the same digest

An immutable application build is tagged with a commit SHA and deployed by digest to controlled environments. Promotion must not rebuild the artifact, while approvals and post-deployment health checks govern release safety.

Commit→CI build & tests→Registry digest→Dev→UAT→Production

02 / IDENTITY ARCHITECTURE

Cross-cloud access without static keys

Azure workload identity obtains a trusted assertion, exchanges it for scoped temporary AWS credentials, then signs only authorised API requests. The example highlights trust claims, least privilege and credential lifetime.

Azure identity→OIDC assertion→AWS STS→Scoped role→SigV4 API

04 / CROSS-CLOUD API SECURITY

Azure CRM to AWS API: two controlled access paths

An illustrative reference architecture based on cross-cloud integration principles. An Azure-hosted application and authorised developers can independently request temporary, scope-limited AWS credentials to call a protected API. This is a conceptual explanation, not an export of an employer's deployment.

Application runtime

Azure-hosted application→Entra workload identity→AWS STS · temporary credentials→SigV4 · IAM-authorised API Gateway→Lambda · AI integration

Authorised developer testing

Approved developer→Interactive Entra sign-in→AWS STS · scoped session→SigV4 · permitted API route

Security boundaries: temporary credentials rather than static AWS keys; separately authorised application and developer identities; least-privilege role permissions; environment-specific access; HTTPS transport. CI/CD deployment identity is a separate trust relationship and not equivalent to runtime API access.
