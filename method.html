METHOD / CODEX / ENGINEERING PRACTICE

AI-accelerated work.
Human-owned outcomes.

Codex is part of how I explore, implement, validate and improve engineering systems. It strengthens the workflow; it does not replace technical judgement, repository ownership or production controls.

01 / THE WORKFLOW

Structured assistance.
Explicit engineering gates.

01 / FRAME

Problem and boundaries

Define existing architecture, functional contract, environment dependencies, acceptance criteria, operational risks and what must remain unchanged.

02 / EXPLORE

Alternatives and trade-offs

Use Codex for repository exploration and candidate implementations; assess security, maintenance burden, cost, reliability and migration complexity.

03 / IMPLEMENT

Bounded changes

Request scoped changes to Terraform modules, workflow templates, tests, PowerShell utilities and documentation—not broad, unreviewed rewrites.

04 / VERIFY

Tests and review

Review diffs, validate Terraform plans, inspect IAM permissions, test deployments, check secrets boundaries and verify environment-specific behaviour.

05 / RELEASE

Controlled promotion

Use source review, approvals and immutable artifact promotion where appropriate, with health checks and rollback or migration recovery agreed before rollout.

06 / LEARN

Operational feedback

Use incident findings, pipeline outcomes and developer feedback to improve module contracts, runbooks, checks and automation.

03 / ENGINEERING STANDARDS

What I do not
delegate to a model.

AI assistance is most useful when the engineer remains accountable for the resulting system and decisions.

✓Production access decisions, permissions and secrets handling.
✓Destructive data migrations or Terraform replacement approval.
✓Claims that tests passed or changes were deployed.
✓Operational readiness, incident response and rollback commitments.
✓Confidentiality obligations and intellectual property boundaries.
